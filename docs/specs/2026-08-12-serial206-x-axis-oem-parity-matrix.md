## 2. Accepted decisions

- **D1 — mask separation.** OEM-literal X preparation performs **no SAP12 or SAP13 write**. The Serial-206 machine configuration expectation is read-only: fresh `GAP12=1` and `GAP13=0`. No retained X parity path may repair, reconcile, or otherwise mutate SAP12/SAP13. One identical tuple `(right-disable param 12 = 1, left-disable param 13 = 0)` must be shared by preparation verification, status, every motion preflight, and tests. The tuple may not be duplicated as drifting literals.
- **D2 — release envelope.** X release coordinates are `0..90263`, inclusive. Preserve the OEM `moveX` effective minimum of `60`, the relative-move inner margin of `20`, and each PositionTable operation's own source clamp. The Serial-206 `WASTE_BIN x=92049` datum is operation data; it does **not** widen the release envelope.
- **D4 — abort naming and scope.** An X-context alias may expose OEM abort only when labeled **aggregate OEM abort**. `ClassControlInterface.forceAbortMotion()` sets global no-24-V host state and invokes every present board; it is never X-only physical scope.
- **D6 — live reference admission remains open.** At the exact deployed live gate, retain an existing X reference only when its durable receipt, board-5 lifecycle generation, controller position, switch state, and operator observation all match the deployed authority. Otherwise one separately approved exact X home mode is the first physical movement and must reach `awaiting_operator_observation` before reference publication. WP0 selects neither physical branch.

## 3. Classification, status, and claim labels

**Classification:** `OEM_LITERAL`, `SERIAL206_ADAPTATION`, `SAFETY_HARDENING`, or `UNRESOLVED`.

**Status:** `exact`, `partial`, `missing`, or `wrong-owner`. Where two are shown, both defects apply.

**Claim labels:**

- `X_SINGLE_AXIS_OEM_PARITY`: only X-exclusive source behavior on board 5/motor 0, after all applicable rows and supervised physical acceptance pass.
- `X_SHARED_COMPOSITE_SOFTWARE_PARITY`: source-shaped software parity for behavior shared with Y/Z/gripper/workflows; it is not physical parity.
- `DEFERRED_FULL_PHYSICAL_PARITY`: full machine/workflow behavior remains deferred until supervised physical acceptance covers every implicated axis, interlock, gripper/plate/tip state, and caller family.

No row in this WP0 matrix grants any claim. “Exact” means exact by direct source/code inspection at the pinned base, not executed proof.

## 6. Required target ownership shape

The target design is one authority, not parallel route implementations:

1. `Serial206OemInitializationProvider` owns X lifecycle, board5 generation, read-only mask verification, preparation, reference/observation, replay fencing, interrupt handling, and SQLite receipts.
2. One X kernel owns direct board5/motor0 primitives and returns source values plus hardened ACK/event/readback evidence.
3. X-bearing XY/moveTo/workflow transactions call the same X admission/kernel; they do not bypass it via generic driver calls.
4. Closed typed robot routes/actions represent each source semantic intent. Existing generic X mutation routes must either delegate without semantic loss or return 410 with the exact replacement.
5. BMS consumes the robot-advertised discriminated action schema and status projection. It must not invent generic forms or infer physical success from HTTP success.
6. Aggregate OEM abort is presented as aggregate everywhere, including when launched from an X card.
